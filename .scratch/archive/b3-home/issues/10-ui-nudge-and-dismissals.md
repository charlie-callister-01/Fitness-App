## What to build

**1. `NudgeCard.razor`** (C-08; named `NudgeCard` to avoid clashing with the Core `Nudge` type). Parameters: `Item` (`Core.Rules.Home.HomeNudge`, ticket 03, merged), callbacks `OnAction(HomeNudge)` and `OnDismiss(HomeNudge)`. Shows `Item.Nudge.Message` as a calm message, **one action button** by `Item.Action` and a **Dismiss** button:
- `MakeUp` shows "Make up"; `DifferentSession` shows "Pick a Session"; `BackUp` shows "Back up"; `None` shows no action button (Dismiss only).
- The component has `role="status"` semantics appropriate for a calm message (not an alert), each button is at least 44 px, Dismiss has an accessible name such as "Dismiss: {message}".
- Keep styles it like an old chatbox via tokens; Clean is plain. Use CSS isolation and existing tokens only.

**2. `NudgeDismissals`** (plain class, **not** a DI service, so no registration or shared test wiring changes): `new NudgeDismissals(IDevicePreferences preferences)`.
- `Task<IReadOnlySet<string>> LoadAsync(IEnumerable<string> keys)` returns which of the given Nudge keys are dismissed.
- `Task DismissAsync(string key)` records one.
- Storage uses `IDevicePreferences.GetAsync/SetAsync` with the per-key preference name `"nudge-dismissed:" + key` and value `"1"`. A missing or blocked store reads as not dismissed; a write that fails never throws into the UI (the interface promises this; do not add try/catch noise unless a test shows it is needed).
- Keys already include the week (ticket 03), so a new week needs no cleanup.
