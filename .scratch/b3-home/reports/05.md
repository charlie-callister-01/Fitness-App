## What changed
- Created `src/Core/Rules/Starting/CustomWorkoutStart.cs` with:
  - `CustomWorkoutStart.Create`: creates an in-progress Workout with `SessionId = null`, `LoggedAfterwards = false`, `StartedAt = clock.UtcNow`, `EndedAt = null`, empty entries, `PainCheck = null`, and `Planned = [.. rows]`.
  - `CustomWorkoutStart.RowsForExercises`: resolves rows for exercise IDs (keeping order, dropping duplicates); for planned exercises looks up the active plan row (accounting for active phase overrides, first session match wins) with Sets, Reps, RepsMax and Cue preserved; for unplanned exercises returns 3 Sets with no reps.
  - `CustomWorkoutStart.RowsForMakeUp`: returns a copy of the session's rows in force that week using `PhaseRules.ExerciseRows`.
- Modified `src/Core/Rules/Starting/WorkoutStarter.cs`:
  - Added `StartCustomAsync(Plan plan, IReadOnlyList<SessionExercise> rows, DateOnly today)` returning `StartOutcome.Continued` if a workout is in progress, returning `new StartOutcome(null, null)` if rows is empty, and creating and committing the new custom workout otherwise.
- Created `src/Core.Tests/Rules/Starting/CustomWorkoutStartTests.cs` covering all acceptance criteria, including verifying that a custom workout made for a missed session leaves that session missed via `WeekScheduleRules.MissedInWeek`.
